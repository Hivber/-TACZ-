# Dragonfly + PNX-style terrain generation

This fork keeps Dragonfly as the server runtime and adds a native Go terrain generator inspired by the generation architecture used by PowerNukkitX (PNX). It does not embed the Java PNX server or add PNX as a runtime dependency.

## Configuration

In `config.toml`:

```toml
[World]
Generator = "pnx"
Seed = 0
Folder = "world"
SaveData = true
```

- `Generator = "pnx"` enables the new generator for the Overworld, Nether and End.
- `Seed` controls deterministic terrain. The same seed and chunk coordinates produce the same terrain.
- `Generator = "flat"` retains Dragonfly's previous flat generator as a fallback.

## Implemented generation

### Overworld

- Continentalness, erosion, ridges, weirdness, temperature and humidity noise fields.
- Warped large-scale terrain, rolling hills, mountain/peak regions, oceans and river valleys.
- Biome selection for plains, forests, birch forest, taiga, jungle, desert, savanna, swamp, snowy plains, meadow, beaches, badlands, ocean variants and mountain biomes.
- Quart biome sections, including cave-biome assignment at lower Y levels.
- 3D cave rooms and tunnels, underground lava/water pockets, bedrock floor, stone/deepslate transition and biome-aware surface materials.
- Deterministic ore veins, trees, leaves, grass, ferns and selected flowers.

### Nether

- Uneven floor and ceiling, cavern space, lava pockets, bedrock boundaries and biome regions.
- Netherrack, basalt/soul-sand style regions, quartz ore and Nether gold ore.

### End

- Central island, surrounding void and deterministic distant island clusters.

## Design and compatibility notes

PNX's generator is organized as a staged pipeline (terrain, biome, surface processing, feature/populator work and final lighting). Dragonfly exposes a different `world.Generator` contract: a generator receives one chunk and fills it, so this port performs the corresponding logical passes inside Dragonfly's chunk-generation call. Cave noise is sampled on a 4x8x4 density lattice and interpolated between samples to reduce per-block 3D-noise cost.

This is a native Go adaptation of the broad PNX generation approach, not a byte-for-byte or feature-for-feature transplant of PNX's Java generator. It does not yet reproduce PNX's complete density-function spline graph, all PNX surface rules, complete feature/populator registry, or large vanilla structures such as villages, temples, monuments, strongholds, mansions, ancient cities, Nether fortresses and bastions. The result is intended as a substantial terrain-generation foundation; exact vanilla/PNX parity requires further staged feature and structure work.

Dragonfly only invokes the generator for chunks absent from the world provider. Existing chunks generated by the flat generator will remain unchanged. Before testing, back up the old world folder and point `Folder` to a new directory (for example `world_pnx`) so a clean world is created without deleting the old save.

## Archive/runtime data

The source archive intentionally omits `.git`, the existing LevelDB world/player folders and the server's NetherNet private key. The key is regenerated automatically on first launch. To retain the old NetherNet server identity, keep a private backup of the previous `keys/server_identity_key.pem` and restore it locally before starting the updated server; do not publish it.
